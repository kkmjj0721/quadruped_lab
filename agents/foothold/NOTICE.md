# 四足注意力选点的来源与适配

本目录由本项目根据论文公开结构独立实现并维护，未移植作者或非官方项目源码。

依据为 [Humanoid Mobility via Attention-based Contacts，arXiv:2610.31608v1](../../paper/2610.31608v1.pdf) 的 Methods「Attention-based Whole-Body Contact Planner」、Eq.1–2（第 13 页），补充材料「Network architectures」（第 20 页）、Table S3（第 22 页）及 Table S5（第 23 页）。实际阅读以上正文与表格，没有运行作者训练或核对作者权重。

- 保留地图逐点嵌入 `3→16`（ELU），地图 CNN `1→16→48`（两层 5×5、padding=2、ELU），融合投影 `64→96`，地形上下文 `96→64→64`（ReLU、逐点计算后 max pooling）。
- 五步本体历史、三维指令与 64 维上下文融合为 `输入→128→128→96`（隐藏层 ReLU）；足别嵌入经 `96→64→192` 的 FiLM MLP（隐藏层 ReLU）生成缩放和平移，按 `scale * shared + shift` 形成足别 query。
- 注意力使用 96 维、32 头、无 dropout。实现按每头缩放点积 softmax 概率求均值；对数域聚合的结果作为 logits。该聚合与 PyTorch 多头注意力默认返回的平均权重约定一致，属于本项目明确的实现约定，不宣称论文逐项规定了投影偏置、初始化或头间聚合的代码细节。选点仅消费权重，因此不创建只服务占用输出的 value／输出投影。
- 监督保留 Eq.1 的三维高斯软标签和 Eq.2 的有效目标交叉熵，带宽 0.1 m；推理采用 Table S5 定量评估的 top-1。所有目标均是输入地图中一个完整的三维候选点，不做多个点的坐标平均。

本项目的明确适配：9 接触体改为 FL、FR、RL、RR 四足，指令由任务提供速度语义；地图来自深度重建，候选 xy 由任务传入并作为模型 buffer 保存。下一次触地标签由任务生成，取消有限视界占用预测、参考动作预训练和 PPO，不在本模块实现锁存或奖励。监督软标签由 GT 候选三维坐标生成，网络前向只读取重建地图。

`foothold_loss` 必须同时接收足目标有效位 `valid[B,4]` 和训练侧几何有效位 `candidate_valid[B,187]`。高斯软标签仅在有效候选上归一化；全部候选无效的样本不计入有效足数量。无效几何可以是 NaN／Inf，参与标签计算前会被排除；标为有效的候选以及实际参与损失的目标必须有限。模型预测分布仍覆盖完整候选集，几何有效位仅服务训练标签，不送入部署网络。

模块检查与数值测试只说明注意力、标签、解码、梯度和持久化接口符合本项目设计，不能证明 Go1 落脚可行、稀疏地形效果或完整 ACP 复现。
